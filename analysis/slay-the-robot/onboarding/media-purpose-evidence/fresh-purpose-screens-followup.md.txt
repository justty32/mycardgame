## E-G1：非 Draft VIEW／SELECT 七項契約復查

**UI 組成：可開工。** [card-selection](../../wf/workflows/game-dev/ui/screens/card-selection.md) 已獨立分開 VIEW 與 SELECT、五欄 Grid、計數、Confirm 和 Back；零候選／恰 min／random 可能旁路完成，不能強等 UI。VIEW opener 是 Combat 四個牌堆按鈕；SELECT opener 是實際產生 ActionPickCards 的效果 owner，休息只是其中一種，不再猜所有關閉都回營地。

**圖像包：可開工。** 面板、Card 圖／框、暫選／反選／不可選理由、足額／返回與空態均有消費責任。查 [Card](../../game/scripts/ui/card/Card.gd)：`init(data,0,false,true)` 接 UI／timer，不接戰鬥刷新；Overlay 的 hover callbacks 是 pass，Card 自身仍有 tooltip timer。新 wrapper 只處理視覺 alpha／scale；Grid 的 layout 和 UI 的 CardGlow.visible 分別有唯一 owner，不會把 reveal 跟暫選 glow 搶同屬性。

**聲音 cue：可開工，原缺鏈已補。** selection-cues 指定 VIEW 開／Back、SELECT 真正改 picked 後的暫選／反選、足額 false→true、Confirm／quick、Back／force 和自動旁路；不是只把 draft 選一張的成功聲拿來用。emit 全域 confirmed 前先存 action、opener、generation、mode、reason 和 picked 快照，避免 listener 清參照後猜原因。VIEW 點牌不發暫選／提交／結果；強制退出不當正常 Back；旁路不發開窗／手動提交音。聲音成功由 opener 的真效果結果決定，selector 不自行播獲得／升級成功。正常例提供開頁1、暫選2、反選1、提交1及可選足額邊緣2的可核對計數。

**動畫時序：可開工，原缺鏈已補。** rest-selection 給候選 ready→reveal／開輸入→暫選／反選→足額→提交鎖→子畫面收尾→效果 owner 接結果→恢復仍有效 opener。Back 清選後走取消，quick_pick 走同一次提交，動畫 completion 不再發 confirmed；零候選／恰 min 不開窗的自動完成不殘留父遮罩。VIEW 不沿用 SELECT action，重疊開啟須拒絕或先取消原 request。與 Draft 的立即點選／Skip 清楚分開。

**實際資料 consumer：已查碼吻合。** [CardSelectionOverlay](../../game/scripts/ui/CardSelectionOverlay.gd) 的 `_on_card_selected` 先反選或 validate 後加入、更新 glow／text／Confirm，再查 quick_pick。Confirm handler 沒重驗數量；Back handler 只依 current action 決定清選／confirmed，沒有 can_back_out guard；set_card_mode(VIEW) 沒清舊 action。這些均標待修。重新查 [ActionBasePickCards](../../game/scripts/actions/card_actions/pick_card_actions/ActionBasePickCards.gd) 與 [ActionPickCards](../../game/scripts/actions/card_actions/pick_card_actions/ActionPickCards.gd)：不足 required 只 finish，恰 min／非 required／random 可直接選並做 child；force 標 cancelled、清 picked，必要時以 confirmed 解除等待。ActionPickCards 生成 child 就 finish，文件沒有誤稱最終效果已完成。

**退出 owner：可開工。** 目前 confirmed／run_ended 只 hide／清 action，VIEW Back 只 hide；卡要到下次 populate 才 queue_free。修補要求新 close 停自己 timer／tooltip／Tween／音訊、清 children／controller reference，且只恢復仍有效原 opener。run_end／換點／離樹先失效 generation，ActionHandler 管取消；舊 reveal／Confirm／child callback 不得套下一個 action。正常 Back 只取消該 request，不能清全域無關 actions；休息 result 回同服務、戰鬥 result 交原 Action、VIEW 無效果 owner，交接已完整。

**專項驗收、第一步／caller／產物：足夠具體。** 第一個工程步驟是建 `tests/ui_card_selection_probe.gd` 及真正 caller。VIEW 接 Combat `_scenario()` 中 `_wait(_player_ready, ...)` 成功後、原勝敗分支前，走四個牌堆 opener→Back，驗 piles／HP／energy／queue 不變。SELECT 由休息 fixture 已 requested 後 runtime load／await；兩合法＋一不合法、min=1/max=2/required=true/quick=false，驗選／反選、上下限、Confirm、Back 允許／禁止及 owner。另 quick=true、零候選、恰 min、random，驗無 modal 也有界解鎖；reveal、暫選、提交後待 child 三階段退出，驗 async、children、tooltip、cue 清理與重入只完成一次。接著補 guard、opener adapter 和 wrapper；需要狀態真結果才補音畫。已確認現 runner 沒有自動 CardSelection／Audio suite，新增 suite 要交 runner owner 接完整 mapping。

## 非阻塞限制與工程交接

兩條首次「找不到完整用途鏈」的缺口已消除。新 API／generation／reason／opener controller、Continue 鎖、handler 重驗、字典 guard、close cleanup、音畫資產和 helpers 全部仍待實作；此處沒有 runtime 綠測。FIRST 列出的 stale 購買、Map visited、結算防重等其他工程缺口維持原判定，本輪不重跑或擴查。

fixture 名稱是建議，不是已存在 API：動畫篇仍示意 `ui_shop_rest_probe.gd`，UI 休息專篇更精確用 `ui_rest_services_probe.gd`；整合時採後者作休息互動 owner，前者可保留商店／靜態組合，避免同一情境跑兩遍。Smoke 僅接靜態組合；有 run mutation 的互動依 UI 專篇接獨立設施情境，避免污染原 Smoke 的 character／mod 探針。這是可由工程 owner 決定的命名／分工，不構成開工阻塞。

新流程把等待中 Continue 預設為拒絕，若產品要求「先取消再離開」才另定政策。音效合併、淡入時長、靜態／減少動態及服務說明內容可在 brief 選擇；不需要為了開始寫失敗 fixture 先決定美術風格。真實輸入、字形／遮擋、視覺時序、聽感及 Dummy／替身證據仍須後續有授權再驗。
