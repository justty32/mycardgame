# Board Lab — 可玩流程設計

[示範包入口](README.md)｜[包資料](pack/mod_info.json)｜[短路線腳本](pack/scripts/ActionGenerateBoardLab.gd)

## 目的與邊界

建立一個題材中立、可從一般新遊戲入口開始的短局，讓後續遊戲作者看到 Phase 2b 與雙盤功能如何由內容資料串接。它同時提供可重現的正常遊戲流程驗收對象。示範包不代替機制邊界回歸，也不宣稱這組數值已經平衡。

角色 `demo_character` 使用 `demo_player` 原型，起始 70 HP、每回合 5 能量，初始章節 `demo_act` 且 `player_act_max = 1`。十張起始牌直接來自角色資料；獎勵卡池涵蓋 common、uncommon、rare，避免預設稀有度抽樣落入完全缺席的類別。沒有商店、休息站、遺物或消耗品池，不要求測試資料生成器補內容。

## 正常狀態轉換

新遊戲初始化角色與牌組後，以 `player_act_id` 呼叫 ActData 的 `act_action_script_path`。包內生成腳本建立四個 LocationData：隱藏的 `location_0` 起點接 `demo_location_entry`，再接 `demo_location_field`，最後接 `demo_location_final`。各節點只有一個後繼；末節沒有後繼且類型為 BOSS。戰鬥事件由同尾碼 `demo_event_*` 明確指定；Act 的事件池仍提供 codex 列舉來源。

起點顯示唯一的 COMPLETE 教學選項 `demo_start`。它不給予物品或修改數值，選取後走既有 RunStartOptions 結束教學及開地圖流程。玩家透過地圖的合法相鄰節點進戰鬥；生成器只建立資料，不直接發戰鬥、勝利或獎勵訊號。

前兩節是 COMBAT，沿用正常擊殺判定、獎勵產生、選牌與回地圖。最後一節是 BOSS，配合一章上限進正常勝利終局。死亡沿用正常失敗終局；重開從新的角色原型與四節點路線初始化。讀檔由已序列化的 LocationData 恢復進度，不重新生成整張圖。

不能把共用 ActionGenerateAct 的層數硬縮成三層：原生成器含固定商店／休息等層位假設。此包透過既有可替換生成接點建立固定鏈；不修改 `act_1`，也不 take over 全域腳本路徑。這個短路線演算法只承諾單章示範，不提供多章隨機生成或分支事件。

## 操作教學與內容分工

第一場用單一敵人展示跨盤選格、「定點打擊」與「守勢」。第二場的兩名敵人讓場域範圍、交換與同盤推擠有可觀察對象。Boss 的防禦與攻擊循環讓玩家需要看意圖；具體數值以敵人 JSON 為準，避免在文件維護第二套平衡資料。

「定點打擊」沒有棋盤選項，是無射程限制的普通單體攻擊。對帶棋盤選項的牌，跨盤 A 規則只免除盤間距離；選格形狀與合法目標仍有效，同盤射程也仍有效。位置不是陣營，交換或跨盤後角色保留原陣營。推擠需要同盤方向，控制區與場域只作用在各自所在棋盤。教學不能用同座標代表兩盤相鄰，也不能把所有位移視作普通步行。

卡牌、場域與規則由其 JSON 維護；遭遇決定每場盤配置及初始站位；此文件只負責整體流程。角色與敵人的三個基礎動畫狀態使用既有圖像，便於完成最小可玩驗收，不代表已完成美術、動畫或音效製作。

## 驗收與下一步

headless 情境必須經正常 new run、教學選項、地圖旅行與出牌入口。不得在測試中偷偷替換牌組、敵人生命、玩家能量或站位來製造成功；需要教學操作的狀態應由牌與回合自然到達。至少覆蓋前兩次獎勵與返回地圖、跨程序 Continue、Boss 勝利、正常死亡及再次開局；另確認包 profile 沒有使用 GlobalTestDataGenerator 的角色、敵人、動畫或卡池。

功能斷言與原始日誌由 runner 留存。數值調整需說明失敗情境並重跑受影響流程，不能把斷言刪掉當修復。headless 的固定劇本不是勝率統計；人工可讀性、卡牌操作感、場域及意圖視覺辨識仍待有 GUI 授權時驗收。擴成正式遊戲前，依 [vertical slice](../../wf/workflows/game-dev/game-flow/vertical-slice.md) 補內容節奏、分支與相應證據。
