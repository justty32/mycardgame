## agent 的持續責任

使用者於 2026-10-19 指定未來由 AI agent 修改程式，允許多 agent 分工，也允許 agent 將可重複的經驗整理成工作流。任務內的實作、驗證、分析與工作流同步由 agent 完成；工程上可自行判斷的步驟不必反覆請示。細則見 [agent-session](../agent-session.md)、[learning](../learning.md)。

使用者於 2026-10-19 補充：工作盡量交由子 agent 執行，主 agent 以交流、協調及整合驗證為主。分工時寫入範圍分開，並依難度選子 agent 模型：雜活用 sonnet、普通工作用 opus、需深入思考用 fable。這項偏好不代表可自行新增無關玩法或啟動排程；核心需求缺資訊時才釐清，並繼續不受影響的工作。

同日指定 `wf/` 作為後續遊戲開發的結構化記憶與操作技能。各 agent 開工前原要求通讀核心規矩；2026-10-19 使用者同意縮減為 4 項必讀（AGENTS.md、WORKFLOWS.md、本檔、目標工作流入口檔），其餘按情境讀，見 [agent-session](../agent-session.md)。子 agent 可以再分派，但須傳遞相同規矩、操作邊界及檔案所有權。工作流應先建立在程式與證據上，涵蓋素材、UI、卡牌、敵人及關卡；MCP 整合留待日後有實際需求再評估。

使用者另要求用不同具體任務模擬首次接手：不依賴對話記憶，以 wf/ 為入口檢查能否開始開發，發現缺口就補工作流與分析。可按 STRUCTURE 下分子工作流，例如關卡下的戰鬥／非戰鬥與地圖設計，另涵蓋整體遊戲流程；拆分依實際職責與演練結果，不只增加檔案數。

同日補充：呈現工作流須細到完整用途，不能只按圖像／聲音／動畫或基礎 UI 元素分類。圖像需區分卡框與卡圖、敵人、UI 等；UI 需涵蓋完整場景，例如對話的頭像／文字／選項與商店的商品／購買狀態。聲音與動畫也要對應整套場景的事件、組合、切換及退出，與素材、資料接線及驗收一起交接。

## 桌面與程序邊界

2026-10-19 起，使用者允許任務範圍內的專案檔案修改與不開視窗的背景檢查；禁止所有桌面、視窗、UI、截圖、焦點操作與啟動 GUI。不得操作、關閉、重啟或終止既有程序。唯讀查詢程序資訊與讀取既有日誌不應改變程序或桌面狀態。

此邊界適用主 agent 及所有子 agent，也適用工具間接啟動的視窗。不得因舊流程列有 Run、capture 或 UI 驗收命令就執行；執行背景檢查前先確認沒有開窗／焦點副作用，不明時先靜態查核。每次派工明示此限制，沿用至使用者另行變更授權；需要 GUI 的驗收保留為未執行，不以猜測替代。

## 版本控制與授權

使用者於 2026-10-19 指定發布至 `justty32/mycardgame`，並授權正常 commit／push。兩者均使用 `justty32` Git 全域身份與既有認證：公司 Windows 經 WSL，家中 Manjaro 用原生 git；兩處全域 user.name 均已核實為 justty32。作業系統登入帳號與 Git 身份不可混為一談，也不需改全域設定。操作以既有 SSH 認證進行；不開登入視窗或瀏覽器。

發布採外層 snapshot 保存 game 原始碼及本地修復，原本 game 的獨立上游 checkout 留在本機。提交前核對一般檔案、來源補丁、可攜證據與排除項，避免誤收巢狀 gitlink；具體佈局與指令見 [開發環境](../dev-env.md)。

沿用已取得的授權；需要新增授權的對外或不可逆操作仍依根 AGENTS.md 處理。回覆以完成結果、驗證與限制為主，通用風格見 [reply-style](reply-style.md)。
