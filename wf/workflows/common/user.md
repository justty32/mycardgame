## 專案方向

文件與回覆使用繁體中文；時區 Asia/Taipei。Slay-The-Robot 作為框架；各款遊戲的參考來源與發行條件記在該遊戲的題材樹，框架文件保持題材中立；workflows 維持 wf/ 非侵入式佈局。相關分析已納入本專案，之後不依賴 PAS。

## agent 的持續責任

2026-10-20 使用者要求降低棋盤與普通卡牌的耦合：棋盤盡量作為掛載於既有戰鬥場景的可選模組；卡牌只帶相關效果，不改普通抽牌、費用、出牌與結算機制。新工作需同時驗真正未掛棋盤與已掛雙盤模式，不能以單棋盤代替未掛載；具體決策見 [decisions](../decisions.md)。

使用者於 2026-10-19 指定未來由 AI agent 修改程式，允許多 agent 分工，也允許 agent 將可重複的經驗整理成工作流。任務內的實作、驗證、分析與工作流同步由 agent 完成；工程上可自行判斷的步驟不必反覆請示。細則見 [agent-session](../agent-session.md)、[learning](../learning.md)。

2026-10-21 使用者確認目標為每場 0~N 盤，並要求先規劃乾淨解耦的程式結構，不先定死部署玩法；優先順序為先交架構與遷移計畫，再依持續任務推進，不以缺少 home／排法等答案阻擋責任分離。方案與實際階段見 [多盤架構](../../specs/multi-board/README.md)。

使用者於 2026-10-20 重申、2026-10-21 再重申：工作盡量交由子 agent 執行，主 agent 負責交流、協調及核對整合；子 agent 可以再分派，寫入範圍分開。模型由派工 agent 自行選擇，子 agent 再派工亦同（2026-10-21 最新指示，取代同日 opus／sonnet 指定）；agent 做事前先通讀 wf 核心規矩（2026-10-20 起重申），簡單工作與雜活除外。這項偏好不代表可自行新增無關玩法或啟動排程；核心需求缺資訊時才釐清，並繼續不受影響的工作。

使用者指定 `wf/` 作為後續遊戲開發的結構化記憶與操作技能。核心規矩的必讀與按情境閱讀入口見 [agent-session](../agent-session.md)；再分派須傳遞相同規矩、操作邊界及檔案所有權。工作流應先建立在程式與證據上，涵蓋素材、UI、卡牌、敵人及關卡；MCP 整合留待日後有實際需求再評估。

使用者另要求用不同具體任務模擬首次接手：不依賴對話記憶，以 wf/ 為入口檢查能否開始開發，發現缺口就補工作流與分析。可按 STRUCTURE 下分子工作流，例如關卡下的戰鬥／非戰鬥與地圖設計，另涵蓋整體遊戲流程；拆分依實際職責與演練結果，不只增加檔案數。

同日補充：呈現工作流須細到完整用途，不能只按圖像／聲音／動畫或基礎 UI 元素分類。圖像需區分卡框與卡圖、敵人、UI 等；UI 需涵蓋完整場景，例如對話的頭像／文字／選項與商店的商品／購買狀態。聲音與動畫也要對應整套場景的事件、組合、切換及退出，與素材、資料接線及驗收一起交接。

## 桌面與程序邊界

2026-10-19 起，使用者允許任務範圍內的專案檔案修改與不開視窗的背景檢查；禁止所有桌面、視窗、UI、截圖、焦點操作與啟動 GUI。2026-10-20 明示禁止螢幕、鍵盤、滑鼠操作，允許 headless Godot。不得操作、關閉、重啟或終止既有程序。唯讀查詢程序資訊與讀取既有日誌不應改變程序或桌面狀態。

此邊界適用主 agent 及所有子 agent，也適用工具間接啟動的視窗。不得因舊流程列有 Run、capture 或 UI 驗收命令就執行；執行背景檢查前先確認沒有開窗／焦點副作用，不明時先靜態查核。每次派工明示此限制，沿用至使用者另行變更授權；需要 GUI 的驗收保留為未執行，不以猜測替代。專案 `.claude/settings.json` 的 PreToolUse hook（`.claude/hooks/block_godot_gui.py`）會擋下未帶 `--headless` 的 Godot 啟動與 `tools/game.ps1`。

## 版本控制與授權

使用者於 2026-10-19 指定發布至 `justty32/mycardgame`，並授權正常 commit／push；同日補充可隨時 push，不必逐次確認。兩者均使用 `justty32` Git 全域身份與既有認證：公司 Windows 經 WSL，家中 Manjaro 用原生 git；兩處全域 user.name 均已核實為 justty32。作業系統登入帳號與 Git 身份不可混為一談，也不需改全域設定。操作以既有 SSH 認證進行；不開登入視窗或瀏覽器。

發布採外層 snapshot 保存 game 原始碼及本地修復，原本 game 的獨立上游 checkout 留在本機。提交前核對一般檔案、來源補丁、可攜證據與排除項，避免誤收巢狀 gitlink；具體佈局與指令見 [開發環境](../dev-env.md)。

沿用已取得的授權；需要新增授權的對外或不可逆操作仍依根 AGENTS.md 處理。回覆以完成結果、驗證與限制為主，通用風格見 [reply-style](reply-style.md)。
