# learning — 將已驗經驗納入工作流

[WORKFLOWS](../WORKFLOWS.md)｜[INDEX](../INDEX.md)｜[共通踩坑](common/gotchas.md)

把可重用的已驗經驗放入現有操作入口，讓後續 agent 能按條件採用、驗收並辨識限制。這不是將每次操作記成新規則。

**何時用**：同一問題第二次出現；或一次已實證，且使用者或當前任務已有明確重用需求。agent 可自主提煉（授權見 [user](common/user.md#agent-的持續責任)）。

**何時不用**：只有推測、一次且未定位的環境故障，或與目前任務無關的功能願望。前兩者先依 [investigation](investigation.md) 查核；未授權的產品工作不因「整理經驗」而擴大範圍。

## Done when

現有工作流或踩坑檔中存在可定位的經驗段落，包含適用條件、最短操作、驗收、不適用情境及證據日期／版本；新增入口的派發與導航連結存在。文件 lint 通過（見 [testing](testing.md#文件檢查修改後必跑)）；實作或測試有變更時，其對應驗證也回傳預期結果。

## 流程

### 先辨識證據與既有入口

回看實際錯誤、最小重現、成功命令、程式位置與驗證結果，記下日期及相關版本／commit。區分「執行成功」「靜態推論」「尚待驗證」，來源說明或註解不能替代實測。一次權限、網路或工具逾時不能推廣成產品缺陷，也不能由成功繞過推出普遍解法。

先查 [WORKFLOWS](../WORKFLOWS.md) 與相關入口，優先補充既有流程。短小且跨工作流的現象與對策放 [common/gotchas](common/gotchas.md)；穩定操作併入對應工作流；缺少會攔住同類問題的驗證則補到 [testing](testing.md) 指向的必要測試。只有新的獨立意圖且既有入口無法容納時才建工作流，不為每個經驗各開一檔。

### 寫出可執行的最小規則

用「條件 → 最短操作 → 驗收 → 不適用」描述，保留會改變判斷的前提，刪掉聊天歷程與無效嘗試。操作優先連到既有命令或測試；驗收須有可觀察結果及失敗判讀，不只寫「應該正常」。已知缺陷與未覆蓋功能不得被成功標記掩蓋。

在同一段落附日期、版本、程式／驗證紀錄連結。過期版本、不同執行方式或不同資料狀態應明列為重新查核條件。若只證明局部可行，就限定局部，不宣稱全流程可用。無足夠證據者暫留原調查紀錄，不升格為操作規則。

### 自主整合與驗證

由 agent 完成提煉、落檔與校驗，不把每條經驗交回使用者逐一批准。平行協作時分開寫入範圍，由整合 agent 同步派發、索引與相關 code map，再跑整體 lint；局部檔案通過不等於導航已完成。仍遵守既有對外及不可逆操作邊界。

先執行受影響的必要驗證；無程式變更的文件更新不另造鏡像測試。回報改了哪個入口、採用哪些證據與仍有的限制。發現新的不相關願望只留原任務邊界，不趁機實作或建立排程。

## 交接

後續遇到條件相符的任務直接採用對應入口。證據被新版程式推翻時，更新或收窄原規則並同步引用，避免留下互相衝突的副本；檔案膨脹時照 [STRUCTURE](../STRUCTURE.md) 整理。
