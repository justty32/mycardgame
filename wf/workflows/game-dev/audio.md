# audio — 聲音製作與接線入口

[遊戲開發](README.md)｜[UI](ui.md)｜[內容](content.md)｜[驗收](validation.md)｜[核實分析](../../../analysis/slay-the-robot/design/audio.md)

從素材到事件與生命週期：製作或採用聲音素材，接上觸發與停止，並留下可核對的驗證證據。

**何時用**：已收到具體聲音需求，要製作或替換音效、音樂與環境音，或調整事件觸發、循環、切換、混音、音量或靜音。
**何時不用**：只有主題構想、還沒有採用要求時，先整理需求再進來；聲音提示背後的傷害／回合規則交 [mechanics](mechanics.md)；原生崩潰依既有邊界處理，不在聲音任務裡順便調查。

## Done when

- 任務交付檔存在，含聲音 brief、需求、採用素材與來源／授權條件、母檔→遊戲檔映射、事件 owner、觸發／停止接線、驗證命令與日誌位置。
- 適用子流程的斷言結果存在；未驗的聽感、匯出與播放範圍明列。沒有聽音驗證時列出待聽項，不宣稱完整音訊驗收。
- 文件 lint 通過（見 [testing](../testing.md)）。

## 流程

先查 [實作核實](../../../analysis/slay-the-robot/design/audio.md)，區分既有能力、已知缺陷與這次才要實作的能力。跨層呼叫與已知缺陷集中在核實分析；流程檔只寫怎麼選、怎麼改、怎麼驗。

接著寫 brief：用途、情緒、辨識優先級、觸發與取消、時長、循環、重疊、變體、bus、音量關係，以及無聲時的視覺替代。成功出牌、攻擊嘗試、扣血命中與被拒絕要分開；重要資訊不能只靠聲音傳達。工程上可決定的規格由 agent 落實，但尚未決定的核心主題不自行填入。

### 來源與製作共同契約

先盤點既有資產與當次可用的工具。沒有音訊生成／合成／轉檔工具時記為缺口；不要把 imagegen 當聲音工具，也不安裝服務或建 MCP。生成素材記錄工具／模型版本、提示詞及原始輸出；錄音或委託記錄製作者、使用範圍、改作與署名要求。框架或插件是 MIT 授權，並不代表外來音檔也有授權。

保留可編輯母檔，以及原始檔與遊戲用檔的對應；命名穩定且有語意，副檔名小寫，變體編號明確。採用紀錄含路徑、來源、規格、處理步驟與 hash；同質清單超過 1 KB 時依 [資料契約](../common/data-files.md) 改用資料檔，不要複製成多張 md 表。

規格記錄實際編碼、採樣率、位元深度、聲道、時長與大小。短音可以先評估 WAV、長曲評估 Ogg，但這不是硬性規格。保留必要的尾音、去除非預期的前置靜音；轉檔不是只改副檔名。記錄峰值、相對響度與同時疊加的餘量；不要把串流平台的 LUFS 當遊戲硬標準，也不以 normalize 代替混音。

### 共同載入邊界

音訊相對路徑包含 `external/audio/...`，是相對 game 根目錄／成品根目錄，不是相對 JSON 所在目錄。FileLoader 使用 runtime 原檔 loader，不會從 `.import` 設定取得循環設定。WAV 一律不 loop；OGG／MP3 才會接 loop 旗標，而且快取只以 path 區分，同一路徑第一次載入時就決定了 loop。缺檔時會回傳非 null 的 fallback，所以要檢查實例不等於 MISSING_AUDIO。

打包的 res 資源與 external 原檔是兩條不同的路：前者要保存實際引用與匯入設定，後者要核對 `exported` feature 與成品旁的 external 複製。從沒做過 export 就標為未驗，不能從本機載入成功推斷成品可用。

## 交接

- 交付素材與來源、每個事件的播放次數／時點、停止 owner、相容性與驗證證據。
- 聲音需要的新 action 與資料欄位交內容／機制流程；來源及引用同步到核實分析；跨媒體時序交 UI／呈現任務 owner。
- 一般接線缺口交工程 owner，不丟給使用者。無聲驗證門檻接 [mixing](audio/mixing.md)；實際播放的聽感驗收須另有授權，未取得前只記未驗，不為了湊完成條件而試播。操作邊界見 [user.md](../common/user.md#桌面與程序邊界)。
