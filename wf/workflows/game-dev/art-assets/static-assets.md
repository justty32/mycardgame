# 靜態素材：從批次製作到資料與場景接線

[素材子流程](README.md)｜[風格版本](style-guide.md)｜[核實來源](../../../../analysis/slay-the-robot/design/art-production.md)

**何時用**：依既定方向製作卡圖、角色立繪／頭像、圖示及背景，或替換同一批素材。**何時不用**：角色狀態／切格走 [animation](animation.md)，命中／投射物走 [vfx](vfx.md)，純排版走 [UI](../ui.md)。

## Done when

交付的素材、母稿或可定位來源、brief 及版本紀錄存在；紀錄填有使用權、風格版本、內容 ID→欄位／節點→輸出檔、SHA-256、實際尺寸與驗收結果。每張圖的解碼／尺寸／引用檢查有結果；接入需求另有目標 loader／場景證據。視覺與匯出未驗者逐項註明，不能只用 PNG 標頭或 Smoke PASS 宣稱完成。

## 流程

### 先定位使用端再決定畫布

從 [來源分析](../../../../analysis/slay-the-robot/design/art-production.md) 開對應原始碼與 scene。對每個待交付內容 ID 記用途、最小顯示尺寸、來源畫布、裁切方式、安全區、透明／不透明要求、朝向／原點、狀態變體與輸出格式。安全區以畫布像素或比例明確表示；不能只寫「留白適當」。新尺寸需連同容器、父節點 scale、文字與命中區評估。

### 先走用途契約，再共用製作步驟

完整卡牌含框／圖／費用／裝飾與狀態，先走 [cards](cards.md)；玩家／敵人／頭目與不同用途裁切走 [combatants](combatants.md)；對話／商店／獎勵／地圖／選單圖像套件走 [interface-assets](interface-assets.md)；戰鬥／節點／主選單背景與分層走 [environments](environments.md)。每篇提供實際 consumer、尺寸來源、缺失接點與專項驗收，再回本篇執行共同來源／輸出流程。只有單張既有圖片且用途契約已固定時，才直接使用本篇。

### 製作與來源保存

插畫／照片／紋理等點陣需求，先讀當前 imagegen skill 並使用其支援流程；編輯既有 SVG、程式圖形或圖示系統則維護原格式。手繪、委製或現成素材留作者、原始來源、取得日期與使用條件。需要的工具不可用就列明欠缺能力及可交接規格，不默默改成不同交付媒材，也不把候選素材說成完成。

母稿置於專案約定的原創設計位置，遊戲實際引用的輸出置於 mod 的 `sprites/` 分類目錄。檔名用穩定內容 ID 與用途，避免以生成序號作內容 ID。記錄母稿→裁切／縮放／去背等處理→輸出，以及實際工具／版本、參考檔 hash；未知模型／seed 寫未提供。輸出檔每次變更更新 hash，重算其派生圖。檔案版本不等於風格版本，兩者都保留。

先完成代表樣本再批次；檢查透明背景是真透明而非棋盤格畫進圖中，主體沒有切斷、四周留白一致。機械檢查只能證明像素／尺寸，審美與辨識度仍需視覺證據。未有可用視覺檢查授權時標待驗，不啟動編輯器或預覽窗。

### 整合：完整路徑與可重現替換

外部欄位填 `external/mods/<mod_id>/sprites/<用途>/<內容_id>.png` 的完整專案相對路徑；角括號是待替換參數。它不是相對資料 JSON。新增 mod 與資料 patch 包裝依 [bootstrap](../content/bootstrap.md)；母稿與未採用候選不放進會掃 JSON 的資料目錄。

FileLoader 依完整路徑快取，不以既有程序熱換檔後的畫面作證據。需要引擎驗證時只用當前已授權的新隔離背景程序。scene 的 `ext_resource`／theme 則走 Godot 匯入與 UID；外部 ImageTexture 不靠 `.import` 完成同一套行為。保留前版與欄位改動對照，方便退回已驗版本，不覆蓋使用者其他素材。

### 驗收層次與失敗定位

先用現有可用的無視窗圖像解碼工具完整讀取每張檔案，核對格式、實際長寬、alpha 像素範圍及是否全透明；僅讀 IHDR 要註明是標頭檢查。工具缺失時明列未解碼，不為此自行安裝 GUI。以 `Get-FileHash -Algorithm SHA256` 留輸出身分，再查引用路徑大小寫、內容 ID 與缺檔。不得把 alpha 通道存在當作透明邊緣正確。

接入任務需在 [bootstrap](../content/bootstrap.md) 的 helper 接線方式加入目標斷言，依 [validation](../validation.md) 跑已授權套件；沒有現成「素材 suite」。目標 loader 結果不能是 MISSING_TEXTURE，且尺寸非零並符合輸出；Card 要等待 display 的 process_frame 後核對實際 texture。背景驗 Act／Location／Event 各自及空白切換；共用圖示驗各使用端，角色頭像驗對應按鈕。既有 Smoke 只表示其既定斷言通過，新增 helper 必須真的被呼叫。

允許視覺驗收後，對最小顯示尺寸與實際背景檢查可辨識性、裁切、透明邊、模糊、色彩語意、文字遮擋與批次一致性；目前禁止桌面／UI／截圖與 GUI，此層保留待驗。發行包另驗 `exported` feature 與 exe 旁 external，不能引用開發載入結果代替。

## 交接

交付紀錄為每個資產保留來源／權利、風格與母稿版本、輸出 hash、接點、檢查證據及待驗狀態。批次同質紀錄大於 1 KB 時依 [資料契約](../../common/data-files.md) 建 `wf-table/1`，以 tabledb 讀寫；只在真有資產時建立紀錄，不建空模板。UI owner 接尺寸／安全區／命中責任，內容 owner 接 ID／資料引用，動畫 owner 接原點與角色母稿。完整日誌留 artifacts；可重用的來源事實回分析，操作接點回本流程。
