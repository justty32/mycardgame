# 對話與商店 — 內容展示到操作結果

[共通契約](README.md)｜[對話 UI](../../ui/screens/dialogue.md)｜[商店 UI](../../ui/screens/shop-rest.md)

**何時用**：製作對話或商店的完整畫面序列。

**何時不用**：只改布局／互動走 [UI 畫面](../../ui/screens/README.md)。標「新增」者為待實作。

## Done when

用途記錄及所需素材／控制器檔存在，包含時間段、輸入與還原政策；專項日誌列實際斷言及退出碼。未落地者標「僅規格」，視覺未驗明列；文件 lint 通過（見 [testing](../../../testing.md)）。

## 流程

先讀共通責任，再以場景篇確認現況，選一個用途建立候選；每次只讓一個 owner 寫同一屬性。

### 對話框：頭像、姓名、文字、選項、關閉

**現況**以 [對話 UI](../../ui/screens/dialogue.md) 為準：DialogueOverlay 一次 parse_bbcode 顯示全文、選項立即建立，沒有 Tween、逐字或說話者入場；名稱是事件名、圖是狀態插圖，空圖路徑保留前張。要有每位說話者姓名、表情與立繪轉場，先由 UI／內容新增映射與節點；本篇需明選空圖「沿用」或「清空」。

**新增製作順序**：美術交面板／邊框、頭像或立繪表情、姓名牌、提示圖與選項狀態，註明共同基準、裁切與文字安全區。先完成一個狀態的靜態排版，再定「面板顯示→姓名／圖同步→本文出現→合法選項開放」。時間值由用途記錄指定，不能推定原版預設動畫；一般文字顯示與減少動態版直接使用完整本文。

若新增逐字控制，本文 owner 綁 dialogue ID＋state ID＋generation；文字揭露期間點擊究竟是補全文或選項需明定，建議先補全文，下一次才執行選擇。不要用字串長度切 BBCode 產生半個 tag，需依已核實的 RichTextLabel API 實作並測 emoji／富文字。選項延後出現不能繞過 option_enabled；拒絕選項保留文字狀態且零 actions。

**操作到下一狀態**：新增「選中強調→鎖本次選項→效果完成→換場或關閉」時，先在 handler 接受點擊時鎖住重複提交，await 後驗 generation 與生存；途中死亡／換地點／run_ended 直接取消文字、表情、音訊與延後選項。dialogue_ended 在致死後也會發，不能僅由它判成功；現有 reset 不等於已有這套重入保護。

**驗收**：長文、無圖與換圖、隱藏／禁用選項、無有效選項 fallback、連點、本文 skip、分支 action 後死亡、等待途中關閉再開新對話；舊回呼不得改新狀態、成功 action 僅一次，下一次打開回到完整基準 alpha／輸入。音訊 owner 與取消 token 依 [對話聲包](../../audio/dialogue-cues.md)。

### 商店：商品入場、購買成功、拒絕與售罄

**現況**：ShopOverlay 沒有商品入場、拒絕搖晃或成交演出。清空重建、買不起的呈現、purchased 與扣款的先後、售罄與 Continue 的程式行為只記在 [商店的程式事實](../../ui/screens/shop-rest.md#商店的程式事實)，本節只寫動態的時點與 owner。

美術先交商品／價籤／面板、hover／disabled、成功提示與售罄標記。動畫根應是商品的內層視覺或新增快照層，Container 仍負責布局。定「資料到位→商品揭示→可購買」，重建清單時只播放新入場的一輪；不要每次價格刷新讓所有商品重新飛入。減少動態版立即完整顯示，用文字與靜態標記表示狀態。

**接受不是交易全部完成**：cue 分為「提交待定→接受／拒絕→效果完成／重建」；成功文字若宣稱錢與物品已到位，要在後續 actions 完成後核對實際結果，單憑 button_up 不得播放成交演出。新增控制器在提交即禁同一商品重按；成功時先快照視覺，避免重建 queue_free 使 Tween 失去目標，僅由交易邏輯扣款／移庫存。拒絕（不足錢、滿槽、無效庫存）維持原商品與可再嘗試狀態，需新增可識別結果事件；不要把「沒收到 purchased」經任意 timer 當拒絕。想保留 SOLD OUT 標記需新增商品槽／售罄資料呈現，不是單加貼圖。

**驗收**：一筆正常交易、錢不足、空槽不足、同商品連點、刷新後 hover、接受但等待途中離店、重回同商店與已售商品；檢查錢／物品／庫存與成功 cue 各一次。關閉使舊重建回呼失效，所有商品控制器釋放，下一次依真實庫存重建，不回滾已接受交易。聲音依 [商店聲包](../../audio/shop-cues.md)。

## 專項驗收與交接

依每節驗收建立有限 timeout 的 fixture；另驗中斷後重開、新資料覆蓋舊資料、減少動態同樣可完成操作，畫面根關閉後零自建 Tween／timer／音訊 cue 殘留。fixture 接線與證據判讀見 [verification](../../ui/verification.md)。交付素材分層、節點根、cue 事件與身分、玩法提交點、重播／取消／減少動態、命令／日誌及未驗；下一 agent 先實作一個用途控制器與對應 helper，不把文件規格當成已有功能。
