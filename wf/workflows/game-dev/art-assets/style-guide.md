# 原創美術方向與風格版本

[素材子流程](README.md)｜[靜態素材](static-assets.md)｜[來源與能力界線](../../../../analysis/slay-the-robot/design/art-production.md)

**何時用**：還沒有美術方向、跨卡圖／人物／圖示／背景的風格不一致，或既有方向需要有界改版。**何時不用**：既有規格下換一張圖直接走 static-assets；核心世界觀與玩法未決走 [planning](../../planning.md)，不以美術工作代定。

## Done when

任務內存在方向 brief、候選取捨、帶版本的風格規格與代表樣本紀錄。紀錄填有採用依據、實際檢查方式與未驗項；沒有生成或視覺檢視時，狀態明列「文字方向提案／代表樣本待製作」，不得宣稱風格已視覺定版。

## 流程

### 輸入與決策範圍

先讀原創需求與場景，寫清玩家應讀懂的主體、情緒、題材、使用畫面、交付類別／數量及既有參考。把使用者已定項與 agent 工程選擇分開：裁切、檔名與輸出尺寸可按 scene 決定；未定核心題材保持候選，不把框架彩色機器人直接升格成本遊戲設定。若任務授權自行定美術方向，可依已定目標選方案並記理由，不額外加確認關卡。

針對真正未定的軸提出少量可比較方向；每個方向說明形狀語彙、材質／線條、明暗層級、色盤、鏡頭／透視、光源與預期縮圖表現。只比較對任務有影響的差異。參考圖僅作參考時仍記來源；採用其圖像或衍生素材前再確認使用條件。不能以相似既有商業遊戲作唯一風格規格。

### 代表樣本先走完整鏈

對四類批次任務，各選一件實際待交付內容作代表：卡圖驗縮小與卡名區、人物驗輪廓與朝向、圖示驗小尺寸辨識及非顏色線索、背景驗角色和 UI 的前後層級。不要為流程增加未要求的新卡或角色。先沿 static-assets 確認輸出規格，母稿與最小實際顯示尺寸都納入檢查，避免只在大圖判斷品質。

製作方法依素材與現有能力選擇；需點陣生成時才讀當前 imagegen skill。未提供參考或工具不可用時可以交文字規格及製作接點，不假造「已看過」的樣本。依當前限制不能進遊戲或開視窗審圖；可做的檔案機械檢查不會把代表樣本自動變成已核可。

### 固定可重用的規格

將採用方向寫成有版本的美術規格，放在該原創設計的持久文件旁。描述固定輪廓比例、線條／邊緣處理、光源方位、色盤與亮度角色、材質及細節密度；另寫各類資產可變的主體／姿勢／背景，不讓每次製作自由改掉共通規則。記參考樣本路徑與 hash、允許及禁止例、裁切安全區、透明與朝向約束；避免把提示詞當成唯一規格。

色彩語意要和內容／UI 對齊。當既有 color、狀態、稀有度有玩法意義時，改配色不能改其含義；狀態圖示需有形狀或符號區別，卡名／費用／規則字不烘入卡圖。沒有視覺證據只能記「待驗辨識度」，不以色盤數值代替可讀性。

### 批次與變更

批次任務使用相同風格版本與代表樣本；每件記來源母稿、產出方法與變體目的。工具／模型／seed 僅記實際可取得值，相同提示詞或 seed 不保證同風格。以代表樣本比較輪廓、筆觸、光源、色彩與細節，不合格者局部返修，保留前版供追溯，未採用候選不接到遊戲。

若只改單件內容而風格不變，重驗該件及其派生縮圖／動畫；若改共通色盤、畫布或比例，提升風格版本並查全部依賴。先重做代表樣本，再替換受影響批次，避免混版。批量狀態超過 1 KB 依 [資料契約](../../common/data-files.md) 存資料檔，欄位包括資產 ID、風格版本、母稿／輸出關係及審核狀態；不在此預建空清單。

## 交接

將風格版本、代表樣本證據與類別約束交 static-assets；人物母稿另交 [animation](animation.md)，能量、打擊與色彩語意交 [vfx](vfx.md) 及 UI。未完成的創意選擇寫成具體待決項，未完成的製作或機械驗證留給下一位 agent；只有確需使用者決定或操作才進 WAIT_USER。
