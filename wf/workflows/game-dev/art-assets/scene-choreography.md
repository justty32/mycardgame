# 場景編排 — 對話、設施、選牌與地圖

[素材入口](README.md)｜[整組場景包](../scene-pack.md)｜[UI 動態](ui-motion.md)｜[UI 畫面入口](../ui/screens/README.md)

**何時用**：交付「進入→展示→操作→成功／拒絕→離開」的完整用途，包含圖片、文字、節點動態與聲音時點。**何時不用**：只改布局／互動走UI，只換圖走素材；人物逐格走 [animation](animation.md)。

## Done when

用途記錄有場景根、素材與引用、狀態時間段、輸入政策、重入／取消與還原、成功提交點及未驗項；實作檔與專項日誌存在。只完成規格時明標未實作，文件 lint 通過，不用幾張素材代表場景已接完。

## 流程

先讀 [共通契約](motion/README.md)，再沿對應用途閱讀實碼來源與驗收。現有overlay多為立即顯示／填資料／清子項；新增序列需要自己的控制器與取消契約。

對話沒有完整speaker／逐字系統，商店purchased先於後續扣款／取得action完成，獎勵點擊不等於草稿已選取，地圖閃爍不等於已有路徑移動；不能把這些資料事件當成任意動畫完成事件。

## 交接

每個用途交成功、拒絕／取消、重開三種情境，沿子流程定素材root、cue owner與唯一提交點。下一agent先在隔離候選接用途helper，再做演出；本輪只靜態文件，不跑Godot／GUI／聲音或生成素材，完整觀感與真實互動保留未驗。
