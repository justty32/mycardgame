# UI 場景與用途 — 從玩家旅程交付整套畫面

[UI 入口與共同技術流程](../../ui.md)｜[完整場景整合](../../scene-pack.md)

**何時用**：需求是「做對話框／商店／獎勵／戰鬥介面」等完整使用情境，需把圖像、文字、資料、操作、聲音與動畫一起交付。

**何時不用**：已有畫面只修一個 theme／focus／字型問題，可直接用 [共同技術流程](../../ui.md#子流程導航)；事件成本、供貨、AI、路線與結算規則仍歸內容／關卡／整局。

## Done when

所選場景篇產出的規格與結果檔存在，包含玩家目的、實際 opener／資料 owner、整套元件和素材包、各狀態結果、cue／取消 owner、fixture 及未驗項；適用的專項檢查回傳預期結果；文件 lint 通過（見 [testing](../../../testing.md)）。

先選畫面及相鄰的前後目的地，再讀該篇的來源。完整畫面不是按鈕／文字等元素總和：要知道輸入何時被接受、效果何時完成、退出時哪些工作必須取消。每篇把已存在 consumer 與新設計分開；「資料有欄位」不視為已接畫面。

### 最小場景規格

沒有既定 UI 設計時，沿現有流程提出一個可回退方案：玩家目的、畫面入口／返回、可見資訊與操作、所需圖像／文字、正常／空值／不可用／選中／確認／取消／結果／離場。先採目前 1200×700 和已知滑鼠流程；其他尺寸與輸入列候選，核心取消／付款／獎勵規則未決才釐清。

把圖像包按消費者指定（背景、插圖／頭像、圖示、panel、互動狀態），把聲音／動畫按語意時點指定（進場、接受、拒絕、結果、離場），並指定唯一 owner 和強制取消結果。圖片與動態不能自己改遊戲資料；完成 cue 不能由普通 hover 或文字刷新冒充。主題字型／長文字／focus 技術用 [元件](../components-layout.md)、[互動](../interaction-states.md)、[文字](../menus-localization.md)。

### 交付與驗收邊界

場景 helper 的實際呼叫鏈用 [verification](../verification.md)。素材已生成、引用已載入、資料結果已驗、視覺可讀、真實輸入可操作、聲音／動畫同步是不同證據；現有 Smoke／Combat 沒有涵蓋所有場景或自動視覺比較。headless 斷言不等於視覺或聽感驗收；需要 GUI、真實焦點或播放的項目標記未執行並明列（操作邊界見 [user.md](../../../common/user.md#桌面與程序邊界)）。

## 交接

將畫面規格交內容／UI／美術／音訊／動畫各 owner，只保留一份資料與完成契約；跨領域時序由 [完整場景整合](../../scene-pack.md) 收斂。多個場景共用元件可抽取，但不得拿共用元件清單取代本篇的整套旅程驗收。
