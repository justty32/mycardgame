# cold-start — 用陌生任務驗證工作流能否帶路

[agent-session](../agent-session.md)｜[經驗回寫](../learning.md)

**本檔是冷接手「演練」（驗證文件能否帶路），不是新 agent 開工步驟；開工步驟見 [agent-session](../agent-session.md) 的「冷啟動」節。**

以沒有當前對話歷史的 agent，從 wf/ 找到任務入口、實作依據與驗收方式；把實際卡住的位置修回文件，再讓另一位陌生 agent 復走。

**何時用**：驗證新 agent 能否接手；新增領域／子工作流後檢查導航；以不同開發任務補強結構化記憶。

**何時不用**：一般功能驗收走 [testing](../testing.md)；只檢查一個連結不必另做演練；沒有獨立讀者時只能標示自查。

## Done when

情境紀錄存在，逐項填有初讀路由、第一個缺口、來源依據、修補入口、獨立復走結果及未驗範圍。修補後的入口與證據連結存在，文件 lint 通過（見 [testing](../testing.md#文件檢查修改後必跑)）。復走未執行或仍卡住的列不得標示完成；導航通過只代表能提出可執行計畫，遊戲功能仍須另有實作與 runtime 證據。

## 流程

### 設計能暴露缺口的任務

協調者先固定原始碼與文件基準、操作邊界、寫入所有權及演練產物。選具體任務，例如獨立 mod 可升級攻擊卡、帶代價的事件、短兩幕流程、替換卡圖與音效；只給驗收目標，不把目標檔名或正確路線預先告訴受測者。產品未決事項保留未知，示意數值不能變成設計決策。

不同任務應涵蓋資料接線、機制、內容評量、非戰鬥與整局轉移、呈現。按實際需求選樣本，不建立無用途的領域空模板。主 agent 指派無歷史 agent（工具支援時，使用不繼承當前對話脈絡的全新子 agent），提供專案根、wf 起點、任務、權限與輸出位置；不附舊討論、其他受測者結論或預期缺口。受測者照 [agent-session](../agent-session.md) 讀 4 項必讀規矩。不能真正隔離歷史時記錄限制，不稱為獨立冷啟動。

### 先記初讀，再修文件

受測者從 WORKFLOWS 選入口，再沿工作流 → 分析 → source/tests 追讀。只靠 wf 指「不靠舊對話或人工口頭補充」，不是禁止查實作。每次額外搜尋記錄所在範圍、問題與原因；既有導航帶到檔案後查符號屬正常操作，靠全 repo 搜尋才找到關鍵責任則記為導航缺口。

先落下不可回填成成功的初始報告，記實際讀過的路由、第一個中斷點、可提出的修改檔與順序、命令的真實存在性，以及來源／證據範圍。只能列計畫時明寫「未實作／未執行」；現有測試 PASS 不能替代候選內容專項。複用歷史結果時保留日期與基準，不寫成當次執行。

將缺口判為導航不足、描述與程式矛盾、缺操作橋接、真正未實作能力或目前授權不允許驗證。前面三類可修文件；真機制問題記錄來源與待測範圍，不藉演練順便改遊戲。需要 GUI 的驗收未執行時，視覺／聽感／輸入未驗是證據邊界，不能以此宣判工作流失敗，也不能當成通過。

### 修補最短操作鏈

每位 owner 只改指定領域。事實與限制放 analysis，方法、前提、最小步驟與交接放工作流；共同測試接線交 testing owner，避免每個領域各造一份 runner 說明。父入口只做路由，子工作流各有適用範圍與 Done when；分層依 [STRUCTURE](../../STRUCTURE.md)，不以長度平均切檔。

協調者將同質情境紀錄放 [資料契約](../common/data-files.md) 所定資料檔。原始長報告可留 artifacts；持久紀錄必須自足地保存初讀發現、修補與證據範圍，不能只連到未追蹤檔。需攜帶 raw evidence 時另存必要且遮罩的副本及雜湊，不把個人路徑／設定／所有工具輸出一併收進 repository。

### 獨立復走與整合

修補 owner 完成後凍結文件，交另一位無當前對話歷史的 agent 相同目標與 wf 起點，不告知修補位置。它自行找到路由並交付：會改的檔案與 ID、執行次序、確實存在的測試入口、需新增的 assertion／接線、目前不能證明的部分。此時才與初讀紀錄對照，填入 reviewer、證據位置及結果。

以三種結果記錄：`pending` 尚未復走；`blocked` 仍不能列出可執行計畫並記具體缺口；`pass` 已由獨立讀者列出上述計畫且核對到實檔。[完整用途演練](../../../analysis/slay-the-robot/onboarding/media-purpose.md)（2026-10-19）使用的 `hold` 與此處 `blocked` 同義，表示已復走但仍有具體開工缺口；保留原報告與歷史欄位，不為統一名稱改寫證據。若復走發現新缺口，修補後由未參與該修補的讀者再次核對受影響路線，不抹去先前失敗紀錄。協調者檢查實際報告和連結後，依 [testing](../testing.md) 跑文件 lint；無程式變更不為演練重跑全部遊戲。

## 交接

首輪方法與證據見 [冷接手紀錄](../../../analysis/slay-the-robot/onboarding/README.md)。導航可執行後依 [game-dev](../game-dev/README.md) 接實際任務；仍需產品決策者回到 [planning](../planning.md)。已完成的演練從 SESSION-LOG 移除，長期缺陷保留在對應分析，不能把靜態演練寫成框架功能已完成。
